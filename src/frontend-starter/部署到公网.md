# SportMate 前端 · 部署到公网

> 目标：拿到一个**助教/同学点开就能用**的公网链接。
> 方案沿用你上次 `calculator-frontend` 的成功经验：**Vercel 静态托管**（免费、不休眠、秒开）。

---

## ⚠️ 先读这一段：顺序不能错

前端和别的项目不一样，**Vite 在构建的那一刻就把后端地址写死进产物里了**。所以：

```
第 1 步  后端必须先部署成功，拿到域名
              ↓
第 2 步  把后端域名写进前端的 .env.production
              ↓
第 3 步  构建前端（npm run build）
              ↓
第 4 步  部署 dist 目录
```

**两个最常见的翻车点**：

| 翻车现象 | 原因 |
|---|---|
| 页面能打开，但一直转圈/报错、一个数据都没有 | 后端地址写错，或者后端还没部署就开始构建前端了 |
| 改了后端地址，重新部署前端还是连旧的 | **只改了环境变量但没重新构建**。Vite 的变量是构建时注入的，改完必须重新 build |

**先确认第 1 步**：浏览器打开你的后端域名 + `/health`，能看到 `{"status":"ok",...}` 才能往下走。

> 后端还没部署？看另一份文档 `sportmate-部署到公网.md`。那份做完再回来。

---

## 第 1 步：确认后端可用

浏览器打开：

```
https://你的后端域名/health
```

期望看到：

```json
{"status":"ok","app":"SportMate 校园运动组局平台","version":"0.1.0"}
```

再顺手打开 `https://你的后端域名/docs`，能看到接口文档页面。

**两个都正常** → 记下这个域名，后面要用。

> 💡 免费实例 15 分钟没人访问会休眠，第一次打开可能要等 30~60 秒。
> 部署完前端后建议自己先点几次预热。

---

## 第 2 步：写入后端地址

打开前端项目里的 `.env.production`，把这一行换成你的后端域名：

```
VITE_API_BASE_URL=https://sportmate-backend-xxxx.onrender.com
```

**格式要求（一个字都不能错）**：

- 必须以 `https://` 开头
- **结尾不要带 `/`**
- 前后不要有多余空格

---

## 第 3 步：构建

在前端项目目录下：

```bash
# 首次需要装依赖（以后不用重复）
npm install

# 构建
npm run build
```

构建成功会出现一个 **`dist/`** 目录，里面有 `index.html` 和 `assets/` 文件夹。

> `npm install` 慢的话用淘宝镜像：
> ```bash
> npm install --registry=https://registry.npmmirror.com
> ```

**构建前先本地验证一下**：

```bash
npm run preview
```

打开 <http://localhost:4173> ，如果**数据和功能都正常**，说明后端地址写对了，可以去部署。
如果这里就不正常，先别部署 —— 问题在环境变量，不在部署。

---

## 第 4 步：部署（三种方式，挑一种）

### 方式 A：Vercel 命令行直接部署（最快，不用 GitHub）

适合**只想赶紧拿到链接**的情况，5 分钟搞定。

```bash
# 首次需要装 Vercel CLI（全局，一次性）
npm install -g vercel

# 在项目目录下执行
vercel

# 按提示走：
#   Set up and deploy?           → Y
#   Which scope?                 → 选你自己的账号
#   Link to existing project?    → N
#   What's your project's name?  → sportmate-frontend（或直接回车）
#   In which directory is code?  → ./  （直接回车）
#   Want to modify these settings? → N
```

第一次会得到**预览地址**。确认能用了，再发布到正式环境：

```bash
vercel --prod
```

**它会自动读取 `.env.production`**，所以后端地址会自动生效。

> ⚠️ Vercel CLI 需要你先登录（会弹浏览器授权）。
> 国内网络访问 Vercel 可能较慢，命令行部署如果卡住就换方式 B。

### 方式 B：GitHub + Vercel 网页（推荐，能自动更新）

适合**后面还要继续改前端**的情况，改完 push 一下自动重新部署。

1. **把前端代码传到 GitHub**
   新建仓库 `sportmate-frontend`（Public），然后把前端项目文件传上去
   （就是你解压 zip 后看到的那些：`src/`、`index.html`、`package.json`、`vite.config.js`、`vercel.json` 等）

2. **在 Vercel 导入仓库**
   打开 <https://vercel.com/new> → 用 GitHub 登录授权 → 找到 `sportmate-frontend` → **Import**

3. **配置构建设置**（Vercel 会读 `vercel.json`，通常已经填好）

   | 字段 | 值 |
   |---|---|
   | Framework Preset | Vite |
   | Build Command | `npm run build` |
   | Output Directory | `dist` |
   | Install Command | `npm install` |

4. **⭐ 添加环境变量（这一步千万别漏）**

   在 Import 页面的 **Environment Variables** 区域点开，加一条：

   | Key | Value |
   |---|---|
   | `VITE_API_BASE_URL` | `https://你的后端域名` |

   > 也可以先不管这一步，导入之后再去 **Settings → Environment Variables** 添加，
   > 但添加完**必须重新部署**：Deployments → 最新那条 → ⋯ → **Redeploy**，
   > 并且要**取消勾选 "Use existing build cache"**，否则用的还是旧的变量值。

5. 点 **Deploy** → 等 1~2 分钟 → 得到域名，形如
   `https://sportmate-frontend-xxxx.vercel.app`

### 方式 C：Render 静态站点（和前端后端都在一个面板）

如果你希望前后端都在 Render 管理，也可以。**但 Render 静态站需要从 GitHub 仓库部署**
（不像 Vercel 那样方便用命令行）。

1. 把前端代码传到 GitHub 仓库 `sportmate-frontend`
2. 打开 <https://dashboard.render.com/select-repo?type=static> → 选仓库 → Connect
3. 填写：

   | 字段 | 值 |
   |---|---|
   | Name | `sportmate-frontend` |
   | Branch | `main` |
   | Build Command | `npm ci && npm run build` |
   | Publish Directory | `dist` |

4. **Environment Variables** 加 `VITE_API_BASE_URL` = 你的后端域名
5. 点 **Create Static Site**

> Render 静态站是免费的、**不休眠**，比它的 Web Service 体验好。
> 但构建需要 `package-lock.json`（用 `npm ci` 的话），如果构建报错就把命令改成 `npm install && npm run build`。

---

## 第 5 步：验证（必做，别跳过）

打开你的前端域名，依次检查：

| 检查项 | 期望结果 |
|---|---|
| 页面能打开 | 看到「🏀 SportMate」和登录框 |
| 注册一个账号 | 成功，并进入主界面 |
| **个人卡片显示信用分 100** | ← 说明**后端连通了**，这是最关键的一项 |
| 活动列表 | 能加载（可能为空，因为还没人发活动） |
| 发起一个活动 | 成功，并弹出详情看到 **4 位签到码** |
| 一句话找局 | 输入「今晚想打篮球」能出结果 |

**如果第 3 项失败**（信用分不显示、一直转圈、控制台报错），就是后端地址的问题，回到第 2 步检查。

用浏览器 F12 打开开发者工具 → Network 面板，刷新页面，
看请求发到了哪个地址 —— 如果不是你的后端域名，说明**构建时环境变量没生效**。

---

## 关于跨域（CORS）

**好消息：后端已经放开了**，代码里是 `allow_origins=["*"]`，
所以你的前端域名（无论 Vercel 还是 Render 给的）都能直接调用，**不需要额外配置**。

如果将来要收紧，改后端的环境变量即可，前端不用动。


## 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 页面能开但一直转圈、无数据 | 后端地址错 / 后端没启动 | F12 → Network 看请求地址；浏览器直接开 `后端域名/health` |
| 控制台 `CORS` 报错 | 后端没起来（不是真的 CORS 问题） | 先确认后端可达 |
| 改了后端地址但没生效 | 没重新构建 | 重新 `npm run build` 或 Redeploy 并**清缓存** |
| 前端域名打开是 404 | Output Directory 填错 | 改成 `dist` |
| 构建报错 `Cannot find module` | 依赖没装 | `npm install` 后重试 |
| 构建报错 `npm ci` 找不到 lock 文件 | 没有 `package-lock.json` | 改用 `npm install && npm run build` |
| Vercel 命令行卡住 | 国内网络访问 Vercel 慢 | 换方式 B（GitHub + 网页） |
| 第一次打开等很久 | 后端免费实例休眠 | 正常，预热几次 |
| 域名打开是 Vercel 登录页 | 开了 Deployment Protection | 项目 Settings → Deployment Protection 关掉 |

---

## 附：如果后端地址将来变了

只需要做两件事：

1. 改 `.env.production`（或 Vercel 的环境变量）
2. **重新构建 + 重新部署**

前端代码一行都不用改。记得**清构建缓存**，否则可能用旧的变量值。
