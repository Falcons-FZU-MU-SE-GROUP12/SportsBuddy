# SportMate 后端 · 前端对接文档

> 给做前端的同学。照着这份文档，**不用看后端代码**就能把页面接起来。
> 文档里的响应示例都是**从真实运行的服务器抓下来的**，不是手写的。

仓库：https://github.com/3054664804/sportmate-backend

---

## 一、最快上手：三种方式你挑一种

### 方式 1：自己本地跑后端（推荐，最稳）

前后端都在你电脑上，没有网络问题、没有唤醒等待，改代码即时生效。

```bash
# 1. 克隆后端
git clone https://github.com/3054664804/sportmate-backend.git
cd sportmate-backend/sportmate-backend     # 注意是两层目录

# 2. 装依赖（只有 4 个包）
pip install -r requirements.txt

# 3. 启动
python -m uvicorn main:app --reload --port 8000
```

启动后：

- 接口文档：<http://127.0.0.1:8000/docs> ← **可以在这里直接点着试每个接口**
- 你的前端请求 `http://127.0.0.1:8000` 即可

> 不需要装数据库，不需要配环境变量。首次启动会自动建表 + 写入 10 个运动项目。
> 需要 Python 3.10+（代码里用了 `X | None` 语法）。

### 方式 2：用部署到公网的地址

如果负责人已经把后端部署到 Render，直接用那个域名（形如
`https://sportmate-backend-xxxx.onrender.com`），把前端里的 `BASE_URL` 换掉即可。

⚠️ **免费实例 15 分钟没人访问会休眠**，你第一次请求可能要等 **30~60 秒**才返回。
前端最好在启动时调一次 `/health` 预热，并给用户一个"正在唤醒服务器"的提示。
文档里的 `api.js` 已经处理了这种情况（会抛出可读的中文提示）。

### 方式 3：你只写前端，我来跑后端

让后端同学在**你们同一个局域网**里启动服务，绑定到所有网卡：

```bash
python -m uvicorn main:app --host 0.0.0.0 --port 8000
```

然后你访问 `http://他的内网IP:8000`。查他的 IP：`ipconfig` → IPv4 地址。

## 三、鉴权：只有两步

```
① 注册或登录  →  拿到 access_token
② 之后所有请求带上  Authorization: Bearer <token>
```

**只有这 4 个接口不需要 token**：`/auth/register`、`/auth/login`、`/sports`、`/health`
（还有 `GET /activities`、`GET /activities/{id}`、`GET /users/{id}` 也允许匿名）。

### 注册

```http
POST /auth/register
Content-Type: application/json

{
  "username": "zhangsan",
  "password": "secret123",
  "nickname": "张三",
  "campus": "旗山校区",
  "skill_level": "beginner",
  "favorite_sports": ["篮球", "跑步"]
}
```

响应 **201**：

```json
{
  "access_token": "9Ju9wsP76G5t0x7vnfetBW3NABe9xcpO926kga-IVRw",
  "token_type": "bearer",
  "expires_at": "2026-11-10T06:14:07.042630"
}
```

字段约束（**这几个前端一定要在提交前校验，否则会收到 422**）：

| 字段 | 要求 |
|---|---|
| `username` | 3~32 位，**只允许字母、数字、下划线**（不能有中文、连字符） |
| `password` | 6~64 位 |
| `nickname` | 1~32 位 |
| `campus` | 默认 `"旗山校区"` |
| `skill_level` | `beginner` / `intermediate` / `advanced` / `any` |
| `favorite_sports` | 字符串数组，如 `["篮球"]` |

### 登录

```http
POST /auth/login
{ "username": "zhangsan", "password": "secret123" }
```

响应同上，也是返回 `access_token`。

### 带 token

```http
GET /me
Authorization: Bearer 9Ju9wsP76G5t0x7vnfetBW3NABe9xcpO926kga-IVRw
```

> token 有效期 30 天。**收到 401 就说明登录过期，请清掉本地 token 回到登录页。**

## 四、错误处理：**`detail` 永远是字符串**

这是本项目特意统一的约定，你不需要为不同状态码写不同的解析逻辑：

| 状态码 | 含义 | 响应示例 |
|---|---|---|
| 400 | 业务规则不允许（如活动已开始） | `{"detail":"活动已开始，无法报名","error":"service_error"}` |
| 401 | 未登录 / token 过期 | `{"detail":"请先登录","error":"service_error"}` |
| 403 | 没权限 / 信用分不足 / 签到失败 | `{"detail":"签到码错误","error":"service_error"}` |
| 404 | 对象不存在 | `{"detail":"活动不存在","error":"service_error"}` |
| 409 | 冲突（重复报名、已满员） | `{"detail":"你已经报名过该活动","error":"service_error"}` |
| 422 | 参数校验失败 | `{"detail":"用户名 长度至少为 3 个字符","error":"validation_error"}` |
| 500 | 服务端异常 | 极罕见，遇到请找后端同学 |

**所以前端只需要这一句**：

```js
if (!res.ok) throw new Error((await res.json()).detail)   // detail 直接就能显示给用户
```

> 注意 HTTP 状态码不能只看 200。**签到失败用 403，满员用 409**，请按状态码区分 UI 反馈。

## 五、直接抄这个 API 客户端

后端目录里带了 [frontend/api.js](frontend/api.js)，**把它复制到你的项目里就能用**，
纯 JS 无框架依赖，Vue / React 都行：

```js
import api from './api.js'

await api.login('zhangsan', 'secret123')   // token 自动保存到 localStorage
const sports = await api.getSports()       // 下拉框数据
const me = await api.getMe()               // 个人资料（含信用分）
const list = await api.getActivities({ only_available: true })
const res = await api.matchBySentence('今晚想在旗山校区打篮球')
```

它已经帮你处理了：

- token 自动存取、自动附加到请求头
- **401 自动清除 token**（登录过期不用你手动判断）
- 中文查询参数自动百分号编码（`sport=篮球` 不编码会直接请求失败）
- 网络失败给出可读提示（覆盖 Render 免费实例休眠的场景）
- 统一抛出 `ApiError`，`err.message` 就是后端的中文提示，`err.status` 是状态码

另外 [frontend/ActivityList.vue](frontend/ActivityList.vue) 是一个**能直接跑的 Vue 3 示例页面**，
把登录、活动列表、一句话找局、报名/退报都用了一遍，抄过去改样式就能当作业用。

## 六、数据结构速查

### Activity（活动）

```json
{
  "id": 1,
  "title": "周三晚篮球 3v3",
  "sport": "篮球",
  "description": "缺 2 人，新手也行",
  "campus": "旗山校区",
  "location": "风雨操场 3 号场",
  "latitude": 26.0565,
  "longitude": 119.1966,
  "start_time": "2026-10-12T06:14:07.169800",
  "end_time": "2026-10-12T08:14:07.169800",
  "skill_level": "any",
  "capacity": 6,
  "gender_limit": "any",
  "fee": 0,
  "status": "open",
  "created_at": "2026-10-11T06:14:07.185968",
  "organizer": {
    "id": 2,
    "nickname": "组织者小王",
    "campus": "旗山校区",
    "reliability_score": 100
  },
  "joined_count": 1,
  "slots_left": 5
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| `status` | `open` 可报名 / `full` 已满 / `ongoing` 进行中 / `finished` 已结束 / `cancelled` 已取消 |
| `skill_level` | `beginner` / `intermediate` / `advanced` / `any` |
| `fee` | **单位是"分"**，显示时除以 100。`0` 表示免费 |
| `joined_count` / `slots_left` | 已报名人数 / 剩余位置，直接用不用自己算 |
| `organizer.reliability_score` | 发起人信用分，可以显示出来增加可信度 |

### ActivityDetail（活动详情，`GET /activities/{id}`）

比上面多两个字段：

```json
{
  "...": "（Activity 的全部字段）",
  "participants": [
    {
      "user_id": 9,
      "nickname": "搭子小李",
      "skill_level": "any",
      "reliability_score": 100,
      "status": "checked_in",
      "note": "带我一个",
      "checked_in_at": "2026-10-11T06:14:42.890574",
      "checkin_method": "code"
    }
  ],
  "checkin_code": "9572"
}
```

⚠️ **两个必须知道的点**：

1. **`checkin_code` 只有发起人能看到**，其他人访问同一个接口返回 `null`。
   所以判断「是否显示签到码」用 `detail.checkin_code != null` 即可，不用比较 user_id。
2. **`POST /activities`（创建）返回的是精简模型，不含 `checkin_code`**。
   创建成功后要显示签到码，需要**再调一次 `GET /activities/{id}`**。

`participants[].status` 取值：`registered` 已报名 / `checked_in` 已签到 /
`attended` 已确认到场 / `no_show` 爽约 / `cancelled` 已取消。

### 我的资料（`GET /me`）

```json
{
  "id": 9,
  "username": "usr141442",
  "nickname": "搭子小李",
  "campus": "旗山校区",
  "skill_level": "any",
  "favorite_sports": [],
  "reliability_score": 100,
  "completed_count": 0,
  "no_show_count": 0,
  "created_at": "2026-10-11T06:14:42.813130",
  "review_average": null,
  "review_count": 0
}
```

`reliability_score` 是**信用分**：低于 **60 分无法报名新活动**（后端会返回 403），
前端建议用红色显示并给个提示，体验更好。

### 报名记录（join / leave 的返回）

```json
{
  "id": 1,
  "activity_id": 1,
  "user_id": 3,
  "status": "registered",
  "note": "第一次来，多担待",
  "is_late_cancel": false,
  "checked_in_at": null,
  "checkin_method": null,
  "checkin_distance_m": null,
  "created_at": "2026-10-11T06:14:07.236706"
}
```

⚠️ **取消报名时看 `is_late_cancel`**：如果是 `true`，说明在开始前 2 小时内取消，
**会扣 5 分信用分**。前端应该在这之前给用户确认提示。

### 签到成功（`POST /activities/{id}/checkin`）

```json
{
  "success": true,
  "method": "code",
  "distance_m": null,
  "message": "签到成功",
  "registration": { "status": "checked_in", "...": "..." }
}
```

### 考勤结果（`POST /activities/{id}/attendance`）

```json
{
  "activity_id": 2,
  "attended": [5],
  "no_show": [],
  "score_changes": {}
}
```

`score_changes` 是 `{"用户id": 分数变化}`，可以直接拿来提示"谁被扣了多少分"。

### 匹配结果（`GET /match` 和 `/match/parse`）

```json
{
  "query": { "sport": "篮球", "campus": "旗山校区", "...": "..." },
  "count": 1,
  "items": [
    {
      "activity": { "...": "完整的 Activity 对象" },
      "score": 100.0,
      "reason": {
        "sport": true,
        "time": false,
        "skill": true,
        "campus": true,
        "distance_km": 0.01,
        "slots_left": 5
      }
    }
  ]
}
```

`reason` 可以直接用来渲染"为什么推荐给你"的标签，比如
「项目匹配」「水平合适」「距离 0.5km」——这是产品的加分项，建议用上。

## 八、时间格式（**最容易踩的坑**）

后端所有时间都是 **ISO-8601 字符串，不带时区偏移，代表 UTC**：

```
"2026-10-12T06:14:07.169800"     ← 这是 UTC 时间，对应北京时间 14:14
```

**前端显示时必须转成本地时间**，否则会差 8 小时：

```js
// ✅ 正确：补上 Z 再解析
new Date(iso + 'Z').toLocaleString('zh-CN')

// 或者
new Date(iso.replace(/(\.\d+)?$/, '$1Z')).toLocaleString('zh-CN')

// ❌ 错误：浏览器会当成【本地时间】，在中国会显示成 06:14（实际是 14:14）
new Date(iso).toLocaleString('zh-CN')
```

**提交时间时**，反过来要给 UTC 时间并带 `Z`：

```js
// 用户选了北京时间 2026-10-12 14:00
const startLocal = new Date('2026-10-12T14:00:00')       // 本地时间
const payload = { start_time: startLocal.toISOString() } // 自动转成 UTC 带 Z ✅
```

> 用 `toISOString()` 是最省事的做法，它永远输出正确的 UTC 格式。

## 九、签到功能的两个实现选择

### 用签到码（简单，推荐先做这个）

发起人把 4 位数字念给到场的人，前端一个输入框：

```js
await api.checkinWithCode(activityId, '9572')
```

### 用定位（体验好，但有前提）

```js
const pos = await new Promise((resolve, reject) =>
  navigator.geolocation.getCurrentPosition(resolve, reject, { timeout: 10000 })
)
await api.checkinWithLocation(activityId, pos.coords.latitude, pos.coords.longitude)
```

⚠️ 两个前提：

1. **必须 HTTPS 或 localhost**，普通 `http://` 域名浏览器会直接拒绝定位。
   所以你本地 `localhost:5173` 能测，部署到 `http://` 的服务器就不能用。
2. 需要用户授权定位，要处理被拒绝的情况。

超出活动地点 **300 米**会返回 403，提示形如
`"你距离活动地点约 1501 米，超出 300 米签到范围"`——直接把这句话显示给用户就行。

## 十、建议的页面拆分

| 页面 | 主要接口 |
|---|---|
| 登录 / 注册 | `POST /auth/login`、`POST /auth/register` |
| 首页（找局） | `GET /match/parse`（一句话输入框）、`GET /match` |

| 活动详情 | `GET /activities/{id}`，发起人显示签到码和考勤入口 |
| 发布活动 | `POST /activities` + `GET /sports` 填下拉框 |
| 我的 | `GET /me`、`GET /activities/mine` |
| 我的评价 | `GET /users/{id}/reviews` |
| 签到页 | `POST /activities/{id}/checkin` |

**发起人才需要做的操作**：看签到码、记录考勤（`POST /activities/{id}/attendance`）、
取消活动。其他用户看不到这些入口——用 `activity.organizer.id === me.id` 判断。

## 十一、联调时出了问题怎么排查

| 现象 | 原因 | 解决 |
|---|---|---|
| 浏览器控制台 `CORS` 报错 | 后端没启动，或地址写错 | 先浏览器直接打开 `后端地址/health` 看能不能通 |
| `Failed to fetch` / 连接被拒 | 后端没启动 | 检查 `http://127.0.0.1:8000/health` |
| 第一次请求卡 30~60 秒 | Render 免费实例休眠 | 正常，加个"正在唤醒"提示 |
| 一直 401 | token 没带上或已过期 | 检查请求头 `Authorization: Bearer xxx` |
| 422 参数校验 | 字段格式不对 | 看 `detail` 里的中文提示，它会指出哪个字段 |
| 中文参数报错 | 没做 URL 编码 | 用 `URLSearchParams`，或直接用 `api.js` |
| 时间差 8 小时 | 没补 `Z` 就 `new Date()` | 见第八节 |
| 签到一直 403 | 定位超出 300 米 / 签到码错 | 看 `detail` 里的具体原因 |
| 报名返回 409 | 已经报过名 / 已满员 | 按状态码区分提示 |
| 报名返回 403 | 信用分低于 60 | 提示用户信用分不足 |

**有个万能排查手段**：把后端的 `后端地址/docs` 打开，
用 **Try it out** 手动调一次同样的接口。如果这里能成功而你的前端不行，
那问题一定在前端（token、编码、地址）。

## 十二、有问题找谁

- 接口返回不符合文档 → 找后端同学（可能是我改坏了）
- 不确定某个字段含义 → 打开 `/docs`，里面有每个字段的类型说明
- 想加新接口（比如"我关注的人的活动"）→ 提给后端同学，改动不大

**后端同学注意**：`/docs` 页面是自动生成的，你改了 schema 它自动跟着变，
所以这份文档里如果有对不上的地方，**以 `/docs` 为准**。
