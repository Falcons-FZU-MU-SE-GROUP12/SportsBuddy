## 四、缺陷

### DEF-03（阻断 / P0）登录不持久化 token —— **已修复**

**修复前现象**：输入正确账号密码，`POST /auth/login` 返回 200 并带回 `access_token`，但页面提示「请先登录」，停在登录页（证据：`02-DEF03-login-blocked-before-fix.png`）。

**根因**：`pages/login.js:56` 调完 `api.login()` 直接 `setSession(await api.getMe())`；而 `api/index.js` 的 `login()` 只发请求、**从未调用 `tokenStore.set()`**。于是紧跟的 `GET /me` 没有 `Authorization` 头 → 401（`http.js:186` 还会顺手清一次 token）。`register()` 有同样问题。mock 模式不校验 token，所以 `verify.mjs` 从未暴露它。

**修复**（`src/frontend/frontend/src/api/index.js`）：

```js
async register(payload) {
  const res = await http('/auth/register', { method: 'POST', auth: false, body: { ... } })
  if (res?.access_token) tokenStore.set(res.access_token)   // 注册即登录也要落盘
  return res
},

async login(username, password) {
  const res = await http('/auth/login', { method: 'POST', auth: false, body: { username, password } })
  if (res?.access_token) tokenStore.set(res.access_token)   // DEF-03：立刻持久化
  return res
},
```

**修复后验证**：重跑本 E2E → 第 2 步 PASS，9/9 全绿；前端 mock 自检 `node tools/verify.mjs` 由 140 项增至 **161 项，全部通过**（无回归）。

### DEF-04（一般 / P2）考勤记录把发起人自动写成「已到场」—— 未修复

**现象**：容量 2、只有 alice 与 bob 报名，发起人执行考勤后：

- 详情页人数变成 **3/2 人 · 名额已满**，参与者列表里多了发起人；
- 发起人信用分 80 → 82（被当作完成一场 +2）；
- 评价页里发起人也成了可评价对象。

**根因**：`src/backend/services.py:637-662` 在 `attended_ids` 非空时无条件为发起人建一条 `attended` 报名记录并重算信用分。注释写「Organisers who show up also earn credit」，但代码无法表达「发起人没到场」。

**影响**：人数显示超过容量；信用分无条件虚增，削弱「防爽约」这一差异点的可信度；发起人无法被记为爽约。

**建议**：把「发起人是否到场」做成独立入参（如 `organizer_attended: bool`），或不计入 `joined_count`，在参与者列表里以「发起人」身份单列。

### DEF-05（展示 / P3）活动卡片把项目图标渲染成英文键名 —— 未修复

**现象**：活动列表卡片左上角的项目图标位置直接渲染出 `badminton`（约 40px 大字），压住活动标题；筛选芯片也显示成「badminton 羽毛球」「basketball 篮球」（证据：`03-activities.png`、`02-login-success.png`）。

**根因线索**：后端 `sports` 表的 `icon` 存的是英文键名（`basketball` / `badminton`），而前端把它当图标字符直接输出（`activities.js:194` 的筛选 label 与 `components.js:197` 的 `sportIconOf()`）。

**影响**：不影响功能，但主列表页视觉明显异常，答辩演示截图上很扎眼。

**建议**：前端加一层 `icon → emoji` 映射（缺省回落 ⚽/🏀），或后端种子把 `icon` 直接存 emoji。
